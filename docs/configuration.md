# Конфигурация

[← README](../README.md)

Скопируйте [.env.example](../.env.example) в `.env` в корне проекта. Скрипты загружают этот файл средствами Node.js. Уже заданные переменные процесса имеют приоритет.

## Переменные развёртывания

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `YC_SERVICE_ACCOUNT_KEY_FILE` | Да | Абсолютный путь к авторизованному JSON-ключу deployer; сам ключ храните вне репозитория |
| `YC_FOLDER_ID` | Да | Каталог Yandex Cloud для ресурсов |
| `PROJECT_NAME` | Нет | Префикс ресурсов; по умолчанию `tg-serverless-example`. Входит в имя бакета, поэтому выбирайте уникальное имя из строчных латинских букв, цифр и дефисов |
| `TF_STATE_BUCKET` | Да | Отдельный S3-бакет для Terraform state; создаётся bootstrap-конфигурацией |
| `TF_STATE_KEY` | Нет | Ключ state в бакете; по умолчанию `<PROJECT_NAME>/terraform.tfstate` |
| `TF_STATE_REGION` | Нет | Регион S3 backend; по умолчанию `ru-central1` |
| `TF_STATE_SERVICE_ACCOUNT_ID` | Только для reset | ID владельца активного S3-ключа; destructive reset сохраняет этот аккаунт и его права |
| `TF_STATE_ENDPOINT` | Нет | S3 endpoint; по умолчанию `https://storage.yandexcloud.net` |
| `BOT_TOKEN` | Да | Токен Telegram-бота; нужен настройке триггера и проверке/инициализации Lockbox |
| `BOT_SECRET_ID` | Нет | Существующий секрет Lockbox; пусто — создать новый |
| `BOT_SECRET_VERSION_ID` | Нет | Версия секрета; пусто — использовать текущую |
| `BOT_SECRET_KEY` | Нет | Ключ записи с токеном в секрете; по умолчанию `BOT_TOKEN` |
| `EXISTING_YDB_ID` | Нет | Существующая serverless YDB; пусто — создать новую |
| `TG_PROXY_BASE` | Да | Префикс Bot API с `/bot` в конце, без токена. Прямой адрес: `https://api.telegram.org/bot`; [настройка Worker](../workers/telegram-proxy/README.md) |
| `TELEGRAM_TRIGGER_NAME` | Да | Имя Telegram-триггера в каталоге; пример задан в `.env.example` |
| `TELEGRAM_AUTH_MAX_AGE_SECONDS` | Нет | Максимальный возраст `initData`: положительное целое число, по умолчанию `3600` |
| `TELEGRAM_AUTH_FUTURE_SKEW_SECONDS` | Нет | Допустимое расхождение часов в будущее: неотрицательное целое число, по умолчанию `30` |

В проект не включены настройки конкретного облачного стенда, персональные URL или рабочие токены. Заполните свои значения перед первым развёртыванием.

## Credentials Terraform backend

Terraform S3 backend читает ключ доступа из стандартных переменных окружения:

```bash
export AWS_ACCESS_KEY_ID=<state-access-key-id>
export AWS_SECRET_ACCESS_KEY=<state-secret-access-key>
```

Это S3 static access key сервисного аккаунта с доступом к state-бакету (например, роль `storage.editor` на бакет). Он не передаётся через `-backend-config`, не попадает в `backend.hcl`, Git или CI. Для локальной работы можно держать значения в непубликуемом `.env` с правами `0600`, но не добавляйте их в `.env.example`. Подробнее — [remote state](terraform-state.md).

## Права deployer

Deployer — отдельный сервисный аккаунт для локального запуска скриптов. Ему нужны права создавать и изменять ресурсы проекта: функции, API Gateway, бакет, serverless YDB, Lockbox, KMS и сервисные аккаунты; назначать им IAM-роли и использовать сервисные аккаунты при публикации.

Скриптам также нужны чтение выбранного Lockbox payload и запись в YDB для миграций и интеграционной проверки. Для существующей базы, секрета и KMS-ключа обеспечьте доступ именно к выбранным ресурсам. Не используйте runtime-аккаунт функции как deployer.

CLI запускается с временной конфигурацией и не меняет активный профиль `yc`. Ключ deployer не загружается в функции.

## Lockbox

При пустом `BOT_SECRET_ID` Terraform создаёт контейнер секрета и KMS-ключ. Скрипт `deploy:apps` добавляет первую версию из локального `BOT_TOKEN` **вне Terraform**. Для существующего секрета скрипт проверяет совпадение токена с выбранной версией; при несовпадении прекращает развёртывание.

В обе функции токен инжектируется ссылкой на запись Lockbox под именем `BOT_TOKEN`. При смене `BOT_SECRET_KEY` имя ENV внутри функции остаётся `BOT_TOKEN`.

`BOT_TOKEN` не передаётся в Terraform variables и не записывается в state как payload секрета. Файл `.env` всё равно содержит секрет: не коммитьте его и храните с ограниченными правами доступа.

## Переменные функций

| Функция | Обычные ENV | ENV из Lockbox |
| --- | --- | --- |
| Bot | `TG_PROXY_BASE`, `TMA_URL` | `BOT_TOKEN` |
| API | `YDB_CS`, необязательные настройки срока авторизации | `BOT_TOKEN` |

`TMA_URL` и `YDB_CS` берутся из Terraform outputs автоматически. Во фронтенд они не передаются; фронтенд использует один origin и относительные `/api/*`.

## Состояние и локальные файлы

`.env`, `.local/`, сборки, ключи из `.secrets/`, Terraform state, планы и `.tfvars` исключены из Git. Произвольный JSON-ключ вне `.secrets/` автоматически не исключается — храните такие ключи вне проекта.

Основной Terraform state хранится в отдельном версионированном S3-бакете, а не в `infra/terraform.tfstate`. Скрипты генерируют несекретный `.local/backend.hcl` и используют `use_lockfile`. Локальный state остаётся только у bootstrap-конфигурации state-бакета и у миграции существующего стенда.

State может содержать чувствительные значения. Ограничьте доступ к state-бакету, не публикуйте его и не запускайте создание инфраструктуры существующего стенда с потерянным state. Первый запуск, миграция и восстановление описаны в [remote state](terraform-state.md).
